## Tech stack & key decisions

- **Next.js 16** (App Router) — breaking changes from training-data expectations: `proxy.ts` not `middleware.ts`, async `params`/`searchParams`/`cookies()`. Read `node_modules/next/dist/docs/` before assuming an API.
- **Prisma v7** with `@prisma/adapter-pg` driver adapter, `prisma-client` generator (not `prisma-client-js`), `prisma.config.ts`. Canonical DB is **Postgres via Neon** — SQLite was abandoned early; local `npm run dev` with a real DB connection is not runnable in this sandbox (network restricted), so verification here is `prisma generate` (schema-only) + `npm run lint` + `SESSION_SECRET=x DATABASE_URL=postgres://x npx next build` (dummy env vars, since the real build script touches a live DB). Live QA happens on the deployed Vercel URL, by the owner.
- **Auth**: custom session via `jose` JWT + httpOnly cookies (not NextAuth), following Next's documented DAL/session pattern. Telegram Mini App auth via HMAC-validated `initData`.

Design tokens (colors/fonts) as CSS custom properties in `globals.css` — see that file for the full palette (`--bg`, `--yolk`, `--yolk-bright`, `--cream`, `--sage`, `--paprika`, etc.) before generating any illustration/image that needs to match brand.
- **Content rendering**: `react-markdown` + `remark-gfm` via `src/components/MarkdownContent.tsx`. Fenced code blocks get a copy-to-clipboard button via `src/components/CodeBlock.tsx` (wired in as the `pre` component override) — reuse this for any prompt/command block in new content, no extra work needed, it's automatic for every ` ``` ` fence.
- **Video**: `Lesson.videoUrl` + `<iframe>` in both the lesson viewer and the single-page material view. Already wired, just set `videoUrl` on a lesson draft to use it. Not used yet in any real lesson.
- **Lesson metadata**: `Lesson.kind` (`THEORY | PRACTICE`, optional) and `Lesson.durationMinutes` (optional). On the course page (`materials/[slug]/page.tsx`), each lesson row shows a circle with either a checkmark (completed) or its **sequential number across the whole course** (computed via `material.modules.slice(0, moduleIndex).reduce(...)` offset — do NOT use a mutating counter inside the render map, ESLint's `react-hooks` rule rejects `variable += 1` reassignment inside JSX-producing callbacks even in a Server Component; use a pure offset calculation instead), plus a `Теория`/`Практика` badge. **`Практика` is highlighted brighter** (`text-yolk-bright font-semibold`) than `Теория` in both `materials/[slug]/page.tsx` and `lessons/[id]/page.tsx` — added 2026-08-11, keep this pattern for any new kind-badge rendering.

## Image production recipe (tested working, follow exactly)

1. **Fonts**: don't refetch from Google Fonts. Reuse the already-resolved woff2 files Next's `next/font` cached under `.next/static/media/` — specifically the Cyrillic-range (`U+400-45F`) variable-weight files for Unbounded and Manrope (grep `.next/static/chunks/*.css` for `@font-face{font-family:Unbounded...unicode-range:...U+400-45F` to find the current filenames, they can change between builds). Base64-inline them into a `<style>` `@font-face` block. Google Fonts `@import`/CDN fails inside Playwright/Chromium in this sandbox (`net::ERR_CONNECTION_RESET`) even though `curl` reaches it fine — never rely on it.
2. **Canvas**: self-contained HTML, `body` sized to the target px (site illustrations: usually 1600×840 or 1600×900; UI-mockup recreations: whatever matches the real screenshot's aspect ratio), dark radial-glow background for brand illustrations (`radial-gradient(ellipse 900px 500px at 50% 0%, #3a2a0f 0%, var(--bg) 55%), var(--bg)`).
3. **Render**: Playwright via `/opt/node22/lib/node_modules/playwright/index.mjs` (not a project dependency — import from that absolute path), Chromium at `/opt/pw-browsers/chromium`. `page.setContent(html)`, `await page.evaluate(() => document.fonts.ready)` before screenshotting so fonts aren't swapped for a fallback.
4. **Save** to `public/guides/*.png` with a descriptive slug-like filename, reference from the lesson markdown as `![alt text](/guides/filename.png)`.
5. **Visual QA every lesson** before committing: extract the lesson's raw content string out of `demo-content.ts` with a small Node script — the naive "find the first and second backtick" approach breaks because lesson content contains escaped backticks (`` \` ``) for nested fenced code blocks; walk the string skipping any backtick preceded by `\` and unescape `\\\`` → `` ` `` afterward. Render through `react-dom/server` + `<ReactMarkdown remarkPlugins={[remarkGfm]}>`, wrapped in a div with classes `prose-iishnitsa prose prose-sm sm:prose-base` (the bare `prose-iishnitsa` class alone does *not* pull in Tailwind Typography's base sizing — headers will render unstyled without also adding `prose prose-sm sm:prose-base`, easy trap). Serve the result via `python3 -m http.server` rooted at `public/` (not `file://` — `react-markdown`'s default `urlTransform` strips non-http(s) `src`/`href` values for security, so local images and the `/_next/static/chunks/*.css` link silently fail to load under `file://`). Screenshot with Playwright, eyeball it, then delete all scratch files (`scratch-*.mjs`, `scratch-*.html`) and kill the http server before committing — never commit scratch/preview artifacts. The compiled CSS chunk filename hash changes on every `next build`, re-check `.next/static/chunks/*.css` each time before wiring a preview.

## Deployment / ops facts (don't rediscover these)

- **Shared production branch**: `claude/telegram-learning-platform-7vet0n` is *not* exclusive to this course work — other parallel sessions push unrelated work to it too (e.g. an `ozon-seller` API integration under `scripts/ozon-seller/`, merged via a completely different branch/PR mid-way through this session). Seeing unrelated commits there after a fetch is expected, not a problem — don't touch or revert them, they're someone else's work. Still always `git fetch` before push/merge and watch for actual collisions on files this course work touches (`demo-content.ts`, `public/guides/`).
- **Sandbox cannot reach**: the owner's live Neon DB, Prisma's hosted DB API, and general internet (confirmed via the egress proxy status endpoint — `www.google.com`, `help.openai.com` etc. all get policy-denied). WebSearch works (server-side, not subject to the local proxy), but WebFetch to arbitrary sites and `curl`/Playwright navigation to arbitrary sites do not. This means **real screenshots of ChatGPT's actual UI cannot be fetched from the internet** either — combined with "Rule 3" above (can't extract pasted images), every UI illustration in this course is a from-scratch recreation, never a real capture.
- **Vercel build**: `package.json` `"build"` script is `prisma generate && prisma db push --accept-data-loss && next build`, plus `"postinstall": "prisma generate"` — this makes Vercel's zero-config `npm run build` fully self-sufficient (handles schema migration automatically on every deploy). Don't remove this.
- **Before any destructive git operation**: check `git status` and `git log origin/<branch>..HEAD` / `git log HEAD..origin/<branch>` first. See "Known issues" below.
- **PRs are merged via squash**: every merge to `claude/telegram-learning-platform-7vet0n` in this workflow uses `merge_method: "squash"`, which creates a *new* commit SHA on the base branch — your local feature-branch commit(s) never become part of that base's history, they just have equivalent content. After each merge, before starting the next lesson's commit, reset the feature branch onto the fresh base tip (`git fetch origin <base> && git checkout -B claude/aishnica-chatgpt-course-dmjuyl origin/<base>`) rather than continuing to commit on the old branch tip. Skipping this caused a real "merge conflict" (GitHub `mergeable_state: dirty`) on PR #40 — not from overlapping edits, but from the feature branch still carrying the pre-squash original commits plus being several commits behind unrelated work (the ozon-seller merges) that had landed on the base in between. Fixed with `git rebase --onto origin/<base> HEAD~<n> HEAD` to drop the stale already-merged commits and replay only the truly new one. Cheaper to just start each new lesson from a freshly reset branch.
