# Telegram QR-бот для маркетплейса

Бот для сценария «QR-код на упаковке → знакомство с брендом → приглашение
в закрытый канал → серия отложенных сообщений (день/неделя/месяц)».
Собирает базу подписчиков (Telegram ID, юзернейм, с какого маркетплейса
пришли, ответы на опросы) в локальную базу SQLite, с выгрузкой в CSV прямо
в чате бота.

## Как это работает

1. Клиент печатает **один общий QR-код** со ссылкой `https://t.me/ИмяБота`
   (без параметра — один QR подходит для всех упаковок и площадок).
   При желании можно печатать разные QR под разные партии/артикулы —
   `https://t.me/ИмяБота?start=МЕТКА` — тогда метка тоже попадёт в базу
   и в CSV-выгрузку.
2. Покупатель сканирует → бот здоровается → кнопка «Продолжить».
3. Бот спрашивает, с какого маркетплейса покупатель пришёл (кнопки
   **Wildberries / Ozon / Яндекс Маркет / Другой вариант** — список в
   `src/marketplaces.ts`). «Другой вариант» просит написать ответ текстом.
4. Сообщение про закрытое пространство + кнопка **«Перейти в канал»**.
   Сам подарок (PDF-капсула/гайд) лежит закреплённым постом в канале —
   бот его не присылает, это делается вручную один раз в самом канале.
5. Дальше — автоматическая цепочка без участия человека (см. ниже):
   через день, через неделю и через месяц после первого контакта.
6. Telegram ID, юзернейм, выбранный маркетплейс, метка партии (если была)
   и ответы на опросы сохраняются в `data/leads.db`.

## Важно проверить до запуска (не техническое)

- **Правила маркетплейса.** Wildberries и Ozon в правилах запрещают вкладывать
  в посылки любые сторонние маркетинговые материалы — за это штрафуют или
  блокируют кабинет. Уточните у клиента, как физически комплектуется заказ
  (свой склад/FBS или склад площадки/FBO), и осознанно оцените риск перед
  печатью тиража.
- **152-ФЗ / согласие на данные.** Первое сообщение бота уже содержит короткое
  уведомление о сборе данных — при желании замените текст на ссылку на полную
  политику конфиденциальности клиента.
- Если призы в `prizes.ts` — не просто скидка, а что-то похожее на розыгрыш
  с ценным призом, уточните у клиента/юриста, не подпадает ли это под
  стимулирующую лотерею (нужно ли уведомлять ФНС).

## Настройка

Нужен Node.js 20+ (проверялось на 22).

1. Создать бота через [@BotFather](https://t.me/BotFather) — **с Telegram-аккаунта
   клиента**, чтобы бот и база подписчиков принадлежали ему. BotFather выдаст токен.
2. Скопировать `.env.example` в `.env` и заполнить:
   - `BOT_TOKEN` — токен от BotFather
   - `BRAND_NAME` — название бренда для текстов
   - `CHANNEL_URL` — ссылка на канал бренда (`https://t.me/название_канала`)
   - `ADMIN_IDS` — Telegram ID через запятую тех, кому доступна команда `/stats`
     (свой ID можно узнать у [@userinfobot](https://t.me/userinfobot))
   - `SUPPORT_URL` — ссылка на тг тех поддержки для кнопки «Есть вопрос»
     (можно оставить пустым и заполнить позже)
3. Установить зависимости и запустить локально:
   ```bash
   npm install
   npm run dev
   ```
4. Написать боту `/start` в Telegram — должен ответить и провести по сценарию.
   Проверить и с параметром: `t.me/ИмяБота?start=test_batch`.

## Тексты сценария

Все тексты и подписи кнопок — в `src/funnel-content.ts` (приветствие, вопрос
про маркетплейс, сообщение про закрытое пространство, тексты «через день» /
«через неделю» / «через месяц»). Правьте и пушьте — код их не проверяет.

Особое внимание — **`MONTH1_TEXT`**: это заготовка под будущую продажу/анонс
(новая модель, закрытая цена и т.п.), в момент запуска там стоит плейсхолдер.
Обновите его в течение первого месяца работы бота, до того как истечёт
30 дней с первых подписчиков. Проверить, как выглядят все три отложенных
сообщения, можно командой `/funnel_preview` (админ-only, шлёт только вам).

## Просмотр базы

**Из самого Telegram (не нужен доступ к серверу):**
- `/stats` в чате с ботом (только для `ADMIN_IDS`) — сколько всего подписчиков
  и разбивка по маркетплейсам.
- `/export` — бот пришлёт CSV-файл со всей базой прямо в чат. Открывается
  в Excel/Google Таблицах, кодировка с BOM — кириллица не съедет.

**Из терминала:**
```bash
npm run stats
```

Файл базы — `data/leads.db`, обычный SQLite (можно открыть, например,
DB Browser for SQLite).

## Автоматическая цепочка после первого контакта

Бот сам, без участия человека, присылает три сообщения каждому подписчику
по расписанию, отсчитываемому от момента, когда он ответил на вопрос про
маркетплейс:

| Когда | Что | Кнопки |
|---|---|---|
| Через 1 день | «Уже успели примерить?» | Очень понравилось / Пока привыкаю / Есть вопрос → ссылка на тех поддержку |
| Через 1 неделю | «Что бы вы изменили?» | Цвет / Длина / Размер / Рукав / Ничего |
| Через 1 месяц | Место под продажу/анонс (см. `MONTH1_TEXT`) | — |

Ответы на первые два опроса сохраняются в базу и видны в `/stats` (сводка)
и в `/export` (по каждому подписчику отдельно) — это и есть готовая
аналитика по первому впечатлению и пожеланиям к доработке.

Технически это отдельный от еженедельной рассылки планировщик
(`src/drip.ts`), проверяющий раз в 15 минут, кому что уже пора отправить.
Ничего дополнительно настраивать не нужно — работает сразу после деплоя.

## Еженедельная рассылка

Бот раз в неделю сам присылает всем подписчикам сообщение (по умолчанию —
каждый понедельник в 10:00 по Москве, настраивается через `BROADCAST_CRON`
и `BROADCAST_TZ` в `.env`).

- **Текст рассылки** — редактируется в `src/broadcast-content.ts` (это
  единственное, что обычно нужно менять; после `git push` подхватится
  к следующей отправке).
- **`/broadcast_preview`** — присылает текст рассылки только вам, чтобы
  проверить перед тем, как он уйдёт всем.
- **`/broadcast_now`** — админ-команда, запускает рассылку немедленно, всем
  подписчикам (для «пропустили понедельник — отправим сейчас» или теста
  на реальной базе).
- Кто заблокировал бота — помечается в базе (колонка `blocked`, видно и в
  `/export`) и больше не получает рассылок, чтобы не копить лишние ошибки.
- Рассылка идёт с паузами между сообщениями — это безопасно для лимитов
  Telegram даже на тысячах подписчиков, просто может занять несколько минут
  на очень большой базе.

## Деплой на сервер

Бот работает в режиме long polling — не нужен домен/HTTPS/вебхук, достаточно
любого сервера с доступом в интернет.

1. Взять недорогой VPS (Timeweb Cloud, Selectel — с российскими картами без
   проблем с оплатой). Достаточно самой младшей конфигурации.
2. Установить Docker на сервере.
3. Скопировать на сервер папку `telegram-qr-bot` (или весь репозиторий) и
   файл `.env` с заполненными значениями.
4. Запустить:
   ```bash
   docker compose up -d --build
   ```
5. Проверить, что бот отвечает в Telegram. Логи: `docker compose logs -f`.

База (`data/leads.db`) сохраняется на сервере в папке `./data` — она не
пропадёт при перезапуске контейнера.

## Кто чем владеет

- **Бот и база подписчиков** — актив клиента (поэтому бот создаётся с его
  аккаунта в BotFather, см. шаг 1 настройки).
- **Сервер/хостинг** — может быть на вашем аккаунте как часть услуги
  (входит в разработку + ежемесячная поддержка), либо сразу передан клиенту —
  этот README достаточен, чтобы развернуть бота заново на любом VPS.
